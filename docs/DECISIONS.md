# 設計與技術決策

## 使用單一 HTML

這個專案的主要交付情境是送禮、手機開啟與另存 PDF，而不是長期營運的應用程式。將 HTML、CSS、JavaScript 與 SVG 放在同一檔案，可以降低分享與保存成本，也不需要建置工具。

代價是檔案會較長，因此透過清楚的 CSS token、語意化 class 與文件說明維持可維護性。

## 不加入照片區塊

原始需求明確指出目前沒有照片。設計改以字體、留白、大型背景日期與滿版色塊建立視覺焦點，避免留下空洞的圖片預留框。

## 使用本地 SVG 動態場景

每個里程碑以一張事件專屬的本地外部 SVG 補足視覺敘事，11 幕都由 `index.html` 載入同目錄資產；原有 inline SVG 只保留為減少動態及列印模式的靜態備援。所有插圖皆為輔助視覺並從無障礙樹隱藏，原始文字仍是唯一的內容來源，也不需要動畫套件或建置流程。

插圖不是獨立的小圖示，而是覆蓋整個事件場景的動態構圖。遠景、中景、主體及近景都在各自的 SVG 內持續運行，不再套用共用整圖漂移；正文只在場景成為主要視區時顯示，讓圖像先建立節奏、文字再成為前景。

2017 場景使用獨立的 `2017_animation.svg`，以深色森林、奶油白恐龍及薄荷綠細節呈現。恐龍整體由左至右循環，巢狀位移與旋轉負責身體起伏及腳步交替；遠近樹層以不同速度反向通過，避免只剩單一角色在固定背景上移動。頁面以 `object-fit: cover` 裁切鋪滿場景；減少動態及列印模式則顯示原人物圓圈的靜態備援。

2018/09—2020/03、2019/01 與 2019 / Summer 分別重製為夜航、深夜廚房與夏季排練室。三幕不再保留早期資產的獨立畫風，而是與全站共用暗底、扁平輪廓、奶油白和薄荷綠色盤；減少動態及列印模式仍回到原本的 inline SVG 靜態備援。

為避免舊飛機動畫由多個不同步關鍵影格造成頓挫，網站改用手工整理的 `2018-2020_flight.svg`。v28 再把它延長為 32 秒右至左的連續夜航：飛機維持同一條空間軸線，攝影機以跟拍、傾斜、推近及俯看改變景別，螺旋槳、雲層與地景各自獨立循環。從 2019/12 起的事件亦改用各自的分層滿版 SVG，而非放大的中央線條圖示。

由於所有場景現在都有持續運動的滿版背景，內文統一放進中央前景面板。細框、半透明深色底與 `backdrop-filter` 提供前後景分離；面板跟隨 `.is-current` 狀態浮現，離開主要視區後隱藏。列印及減少動態模式移除模糊與進場限制，確保內容始終可讀。

背景動畫不再和 `IntersectionObserver` 的可見狀態綁定：11 張外部 SVG 載入後即持續播放。每一幕都由 SVG 內部直接建立多層連續運動，不再套用共用的整圖漂移或斜向掃光。遠景、建築／山景、前景線條及人物／交通工具以不同速度移動，循環重設都在畫外完成。

後半段原本使用霓虹漸層、泛光與中央巨大象徵物，容易形成制式生成圖感，也讓「動畫」只剩局部原地旋轉。v24 改採日系平面海報語彙：有限色盤、乾淨幾何輪廓、大片留白與側向行進節奏。洗衣機滾筒、面具表情等仍可保留局部動作，但只作為穿越整幕場景中的次要細節。

v25 將同一原則擴大到前四幕，並把所有里程碑統一為暗底。為了讓手機連續滑動時仍能立即看出場景交界，使用兩個同色系基底 `#111923` 與 `#20313b` 按時間順序交錯；不以十一種不同色彩製造區隔。構圖先在 360—430px 的手機橫向場景比例確認主體與安全區，再向桌面寬度延伸。

v26 將視覺目標由「一致的平面海報」提升為「原創的電影化日系動畫語言」。參考的是多層視差、跟拍、推拉、仰俯視與前景遮擋等動畫攝影原則，不複製特定工作室的角色或既有鏡頭。每幕延長到約 28—36 秒；所有 SMIL 動畫皆無限重播。第一批以森林、城市玻璃與鳥居縱深三種差異最大的空間驗證這套系統。

使用者指出初版 2017 把森林跟拍、腳步特寫及仰視近景直接切開，雖有三種景別卻缺少空間與動作連續性。因此 v27 廢除「每幕一定要三段硬切」的假設：2017 改為 34 秒單一長鏡，攝影機在同一片森林內跟拍、推近、抬升並回位，景別變化由前景樹幹遮擋與多層視差自然形成。後續場景可選連續長鏡或連貫節拍，但必須維持同一空間軸線與動作因果。

v28 完成第二批四幕：夜航採右至左的空中跟拍與傾斜；深夜廚房由門口遠景持續推至托盤近景；夏季排練室以交叉人物動線配合順時針環繞；返台場景沿海左至右跟拍後升鏡露出聚落。四幕不共用同一種方向或視角，循環分別藏在雲層、蒸氣、窗框或隧道遮擋之下。

v29 完成第三批及全站動畫節奏統一。舞台從觀眾席推入並右至左跟拍首演角色；群體表演利用鏡面倒影及逆時針環繞建立多人空間；面具課由懸掛面具向下移至橫向穿越的表演者，再抬鏡回到面具；結尾則從人物近景持續拉遠與升高，讓道路、山景與星空逐層展開。11 幕全部統一為 `1440×800`、30—36 秒週期，主方向依時間交錯，相鄰暗底使用不同色相，所有循環接點都位於畫外或由布幕、鏡框、面具、雲層等場景內物件遮擋。

2024/09—2025/05 的文字量遠高於其他里程碑，因此不再使用單欄堆疊。前景框內保留原文順序及語意關係，但以左側「課程／稱讚」、右側「老師／引言」兩欄同時呈現，降低場景高度且不刪減文字。

為避免文字遮住滿版 SVG 的中央主體，前景面板由正中央移至下方中央，並縮小最大寬度、字級、行高、段距與內距。面板底色降低為 30% 不透明度，僅保留 10px 模糊及細框作為必要分層；這項調整不刪減或改寫任何內容。

## 所有尺寸統一漢堡選單

桌面與手機都使用右上角漢堡按鈕開啟全螢幕年份選單，保持固定導覽的視覺一致性，也讓桌面首屏與滿版動畫保留更多留白。

## 採用極簡編輯式視覺

內容本質是一段人物旅程。新版移除卡片、圖示、章節口號、背景紋理與交錯排列，讓原始文字、年份與留白成為主要視覺。

## 單向全寬時間軸

手機與桌面都維持由上而下的單向閱讀。事件以直接相接的全寬場景呈現，場景略短於完整視窗以減少捲動距離；桌面只增加內容寬度與左右留白，不做交錯時間軸。

手機為了縮短場景又避免圖字重疊，改用日期獨佔首列、插圖與文字分居左右欄的網格。短內容維持約三分之一個舊場景高度，長內容則允許自然增高，以可讀性優先。

桌面日期不再使用中央大型背景字，而是全部以相同字級固定在場景左上角。插圖活動範圍從日期下方開始，讓時間資訊在各種桌面比例都維持清楚且不被圖形覆蓋。

## 單一強調色

全站只用冷調薄荷綠標示年份、閱讀進度與目前導覽狀態，其他內容維持暖白與近黑。使用者明確不喜歡橘紅，因此後續設計不得恢復橘紅色。

## GitHub Pages

網站以靜態 `index.html` 作為唯一主要網站與 GitHub Pages 根頁面，不使用伺服器端功能、建置框架或絕對站內路徑。主要網站不再保留內容完全相同的相容副本。

## 前端四碼入口

分享時由獨立的 `access.html` 使用 `0916` 四碼入口作為輕量視覺門檻，正確後前往 `index.html`。密碼頁與主要網站完全分離，避免為了入口而維護兩份相同網站。這不是安全驗證：知道 `index.html` 網址的人、公開 repository、HTML 原始碼及靜態資源仍可直接查看內容，不應承載真正敏感資料。

## 不使用框架

目前只有一頁且沒有資料流、路由或後端需求。原生技術已足以完成響應式排版、浮現動畫與閱讀進度，加入框架只會增加維護成本。

## 文件與成品分離

可直接開啟的 HTML 保留在根目錄。需求、原始文案與設計說明集中放在 `docs/`，讓根目錄保持清楚，也避免紀錄文件和成品混在一起。

## SCROLL 指示中間靠左定位

首屏的 `[SCROLL]` 標籤與動態引導線曾因靠左對齊，在手機短螢幕或向下滾動時與頂部固定導覽列左側的「龔龔里程碑」文字發生同軸重疊。最終決定將容器側邊內距歸零，指示器水平定位設定為「中間靠左」（手機 `margin-left: clamp(32%, 36vw, 40%)`、桌面 `margin-left: clamp(30%, 34vw, 38%)`），徹底避開固定站名區域（X ≈ 20–100px），在所有捲動狀態下皆有乾淨舒適的留白。

## 2024/09—2025/05 回歸標準單欄版型

早期為容納陽光劇團老師長段引言而特別設計了雙欄結構（`.event--course`、`.course-copy`）。在使用者決定精簡內容並移除老師引言後，雙欄版型已無必要且破壞全站統一的節奏。因此全面拆除雙欄樣式，回歸與其他 10 個里程碑完全一致的置中單欄 `.event-body` 前景面板。

## 全站 11 幕全景 SVG 動態與手繪獨立動畫美學

摒棄「中央單一物件微幅呼吸」的靜態插圖感，全面重製為 11 幕滿版日系手繪獨立動畫（參考 Izumi Tanaka 風格）：包含全屏橫跨位移、縱深穿梭、多層視差滾動與無縫接點循環。所有動畫節點全部採用原生 SMIL `repeatCount="indefinite"`，頁面載入即永續運行，零外部相依性且效能極高。
